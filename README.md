# COIN QUEEN
## UNIT $LOID
### Electronic Cash System

Queen is an experimental peer-to-peer electronic cash system written in Python.

The project explores whether a separate blockchain can be used for direct peer-to-peer exchange without requiring a predefined fiat price.

The experiment does not assume that Queen is useful. The purpose is to test it in practice and document the results.

Existing cryptocurrencies and stablecoins may already provide convenient payment options. If existing solutions are sufficient, Queen may not be necessary.

The experiment is ongoing.

---

## Supply

Queen currently uses the following supply parameters:
```text
- Maximum supply: 1,000,000 QUEEN
- Premine: 0
- Decimal precision: 8
- Initial block reward: 1 QUEEN
- Halving interval: 500,000 blocks
```
There is no predefined fiat value for QUEEN.

The project does not define an initial USD, EUR, or other fiat exchange rate.

The resulting blocks can be independently verified from the block data, nonce, and Proof-of-Work algorithm.

The purpose is not to claim that mining results prove Queen is useful.

They demonstrate that the blockchain and mining process can be tested and reproduced.

## Current Experiment

The current experiment asks a simple question:

Can two people agree on a value denominated directly in QUEEN and exchange it without first establishing a fiat price?

For example, two people could agree that a service is worth:

```text
2 QUEEN
```

without first defining:

```text
2 QUEEN = $X
```

This separates direct exchange from market valuation.

The experiment does not assume that this model is better than existing cryptocurrencies or stablecoins.

Existing solutions may already be faster, simpler, or more convenient.

If Queen turns out to be unnecessary for this use case, that is also a valid experimental result.

I don't know yet whether Queen has a practical purpose.

That's what I'm testing.

Features

Blockchain

Each block contains information such as:
```text
- Block height
- Timestamp
- Difficulty
- Merkle root
- Transactions
- Previous block hash
- Nonce
- Proof-of-Work result
```
The block hash is independently reproducible from the block data, nonce, and mining algorithm.

Proof of Work

Miners repeatedly test different nonce values until the resulting hash satisfies the network target.

Example:
```text
Block        : 0
Difficulty   : 1
Nonce        : 3232863
Chain        : 0000076817c4822c174530ec4a33b3b51a7fa737a01fe4e23f87fcd3b31599d6
```
A valid block can then be verified independently.

Transactions

Queen uses a UTXO-based transaction model.

Transactions contain:
```text
- Inputs
- Outputs
- Transaction ID (TXID)
- Version
- Timestamp
- Message
```
Verification

Queen includes a block verifier.

The verifier recalculates the block result and compares it with the stored chain value.

Example:
```text
Stored    : 0000076817c4822c174530ec4a33b3b51a7fa737a01fe4e23f87fcd3b31599d6

Result    : 0000076817c4822c174530ec4a33b3b51a7fa737a01fe4e23f87fcd3b31599d6

Status    : VALID
Match     : True
```
The purpose is simple:

Do not trust the stored hash. Calculate it again.

Clone the repository:

```text
python3 -m pip install -r requirements.txt
```

Mining

Start the miner:
```text
python Loid_miner.py
```
The miner displays information such as:
```text
MINING #0
NONCE 3212000
HASHRATE 3272 H/s
HASH ...
```
When a valid Proof of Work is found:
```text
===================================
       BLOCK FOUND
===================================
```
The block is then submitted to the node for validation.

The node may reject a block if its Proof of Work or other consensus rules are invalid.
